## What closed the 112-tag gap (2026-08-21)

The 112 unresolved tags reported after the corrected-seed-rule repackaging
(prior revision of this file) were not a naming accident: they were the
mechanical symptom of item-level re-classification issue LionSR/TNLean #6801
(closed by PR #6806, schema v4) never having been applied to this branch's
`blueprint/` tree, which still carried run 1's whole-file `>=50%`-item-
fraction chapter selection. Repair method:

1. Ran `scripts/qic_blueprint_boundary_report.py` (schema v4, carried on
   `LionSR/TNLean` since PR #6806/#6818) against a read-only TNLean snapshot
   at `b51276ece7fcbe1cc845f6548106f3796c638204` -- the exact commit this
   branch's own Lean-tree dry run (`docs/extraction_dryrun3_report.md`)
   used -- with its mover set substituted for this branch's
   `docs/movers.txt` (512 files; `check_import_direction.py`'s own
   `mover_files()` at that commit is the narrower 498-file CI-guard
   boundary, not the corrected extraction boundary, so it cannot be used
   unpatched). This produced an authoritative item-level QIC/TN disposition
   for every one of the 4,809 theorem-like blueprint environments and every
   non-item block in TNLean's blueprint, matching PR #6806's own headline
   counts in shape (mixed physical files: 47; `qic_to_tn` edges: 1 `\uses`
   + 1 reference, both now resolvable/fixed).
2. For the 10 physical files responsible for all 112 tags, replaced this
   branch's stale whole-file copy with an item-level reconstruction: every
   block (item or non-item) whose disposition is `qic` or `shared` is kept,
   using its *current* TNLean source text (so `\lean{}` tags already
   corrected upstream, e.g. the `MPSTensor.*` to `Kraus.*` rename in the
   Wielandt span-growth lemmas, are picked up automatically); every block
   disposed `tn` is dropped. Retained bytes are copied verbatim from the
   TNLean snapshot; no statement text was edited by hand.
3. Repaired the one remaining `qic`-to-`tn` `\uses` edge this produced
   (`lem:trace_transfer_map_left_canonical` in
   `chapter/ch04_channels_transfer_map_foundations.tex`, which cited
   `def:left_canonical_tensor` -- a label removed as `tn`-disposition in
   this same pass) by dropping that one argument from its `\uses{...}` list;
   the statement text is unchanged.
